# Linux Logs and Monitoring

## 1. Introduction to Linux Logs

Linux logs are records of events and activities that happen inside a Linux system.

They help administrators and DevOps engineers understand:
- What happened in the system.
- When an event occurred.
- Which application or service generated an event.
- Why an application or service failed.
- Whether unauthorized access was attempted.
- Whether the system is experiencing performance problems.

### Why are logs important?

Logs are useful for:

1. Troubleshooting application failures.
2. Monitoring system activities.
3. Detecting security issues.
4. Investigating system crashes.
5. Identifying service failures.
6. Understanding user activities.
7. Maintaining system reliability.

**DevOps example:** If a web application stops responding, an engineer checks application logs and system logs to identify the reason for the failure.

## 2. Linux Log Directory

Most Linux system logs are stored inside:

```bash
/var/log
```

Navigate to the directory:

```bash
cd /var/log
```

List log files:

```bash
ls
```

Display detailed file information:

```bash
ls -lh
```

### Important Linux log files

| Log file | Purpose |
|---|---|
| `/var/log/syslog` | General system messages on Debian/Ubuntu |
| `/var/log/messages` | General system messages on many RHEL-based systems |
| `/var/log/auth.log` | Authentication and authorization events on Debian/Ubuntu |
| `/var/log/secure` | Authentication and security events on many RHEL-based systems |
| `/var/log/kern.log` | Kernel-related messages, where configured |
| `/var/log/dmesg` | Boot and kernel messages, where stored |
| `/var/log/boot.log` | Boot-related messages, where available |
| `/var/log/cron` | Cron job logs on systems configured to use this file |

**Important:** Log file names and locations vary between Linux distributions and configurations. Some systems primarily store logs in the systemd journal.

## 3. Types of Linux Logs

### 3.1 System Logs

System logs contain information about operating system activities.

Examples:
- System startup and shutdown.
- Hardware events.
- System errors.
- Background processes.

### 3.2 Application Logs

Application logs contain information generated by applications.

Examples:
- Application startup.
- Application errors.
- Database connection failures.
- API request failures.

### 3.3 Authentication Logs

Authentication logs record login and security-related activities.


- `Space` – Next page.
- `b` – Previous page.
- `/ERROR` – Search for ERROR.
- `n` – Next search result.
- `q` – Exit.

### 4.3 head

Displays the first lines of a file.

```bash
head /var/log/syslog
```

Display the first 20 lines:

```bash
head -n 20 /var/log/syslog
```

### 4.4 tail

Displays the last lines of a file.

```bash
tail /var/log/syslog
```

Display the last 50 lines:

```bash
tail -n 50 /var/log/syslog
```

### 4.5 tail -f

Continuously displays new log entries as they are written.

```bash
tail -f /var/log/syslog
```

Stop monitoring with `Ctrl + C`.

**DevOps use case:** Monitor application logs while restarting or testing an application.

### 4.6 grep

Searches for specific text inside files.

Syntax:

```bash
grep "pattern" filename
```

Find ERROR messages:

```bash
grep "ERROR" /var/log/syslog
```

Ignore uppercase/lowercase differences:

```bash
grep -i "error" /var/log/syslog
```

Display line numbers:

```bash
grep -n "ERROR" /var/log/syslog
```

Search recursively inside a directory:

```bash
grep -r "ERROR" /var/log/
```

Display lines that do not match:

```bash
grep -v "INFO" application.log
```

## 5. Log Monitoring with journalctl

`journalctl` is used to view and investigate logs collected by systemd-journald.

Systemd-journald collects system and service messages and stores them in the systemd journal.

### 5.1 View all available journal entries

```bash
journalctl
```

### 5.2 View the latest entries

```bash
journalctl -n 20
```

Displays the latest 20 entries.

### 5.3 Follow logs continuously

```bash
journalctl -f
```

Similar to `tail -f`, but follows journal entries.

### 5.4 View logs from the current boot

```bash
journalctl -b
```

### 5.5 View logs from the previous boot

```bash
journalctl -b -1
```

This requires previous boot logs to be available.

### 5.6 View logs for a particular service

```bash
journalctl -u nginx
```

View the latest 50 entries for Nginx:

```bash
journalctl -u nginx -n 50
```

Follow Nginx logs:

```bash
journalctl -u nginx -f
```

### 5.7 View logs within a time range

```bash
journalctl --since "1 hour ago"
```

```bash
journalctl --since "2026-11-10 10:00:00"
```

```bash
journalctl --since "2026-11-10 10:00:00" --until "2026-11-10 12:00:00"
```

### 5.8 View error-level messages

```bash
journalctl -p err
```

Common priority levels:

| Priority | Meaning |
|---|---|
| 0 | Emergency |
| 1 | Alert |
| 2 | Critical |
| 3 | Error |
| 4 | Warning |
| 5 | Notice |
| 6 | Informational |
| 7 | Debug |

For example:

```bash
journalctl -p warning
```

### 5.9 View kernel messages

```bash
journalctl -k
```

### 5.10 Check journal disk usage

```bash
journalctl --disk-usage
```

**Important:** `journalctl` reads the systemd journal. It does not automatically display every application log file on the system.

## 6. dmesg Command

`dmesg` displays messages from the Linux kernel ring buffer.

Syntax:

```bash
dmesg
```

Display readable timestamps:

```bash
dmesg -T
```

Display the latest 20 messages:

```bash
dmesg | tail -n 20
```

Search for error messages:

```bash
dmesg | grep -i error
```

Search for USB-related messages:

```bash
dmesg | grep -i usb
```

### When is dmesg useful?

- Investigating hardware problems.
- Checking device detection.
- Troubleshooting kernel messages.
- Investigating memory and driver issues.

## 7. Understanding Log Levels

Applications and services commonly categorize log messages by severity.

| Log level | Meaning |
|---|---|
| DEBUG | Detailed information for debugging |
| INFO | Normal application activity |
| WARNING | Something unexpected happened, but the application may continue |
| ERROR | An operation failed |
| CRITICAL | A serious failure requiring attention |

Example:

```text
2026-11-10 10:00:00 INFO Application started
2026-11-10 10:02:00 WARNING High memory usage
2026-11-10 10:03:00 ERROR Database connection failed
2026-11-10 10:04:00 CRITICAL Application unavailable
```

**Interview point:** ERROR messages indicate failed operations, while WARNING messages indicate potential problems that may not have caused a failure yet.

## 8. Log Rotation

Log rotation is the process of managing log files by rotating, compressing, and removing old logs.

Why is log rotation required?

- Log files can grow very large.
- Large logs consume disk space.
- Old logs may no longer be needed.
- Managing log files improves system maintenance.

Linux commonly uses a utility called `logrotate`.

### Important logrotate files

Main configuration:

```bash
/etc/logrotate.conf
```

Additional application-specific configurations:

```bash
/etc/logrotate.d/
```

View the main configuration:

```bash
cat /etc/logrotate.conf
```

List application configurations:

```bash
ls /etc/logrotate.d/
```

### Common logrotate directives

| Directive | Purpose |
|---|---|
| `daily` | Rotate logs daily |
| `weekly` | Rotate logs weekly |
| `monthly` | Rotate logs monthly |
| `rotate 7` | Keep 7 rotated files |
| `compress` | Compress rotated logs |
| `delaycompress` | Delay compression until the next rotation |
| `missingok` | Do not report an error if the log file is missing |
| `notifempty` | Do not rotate an empty log file |
| `size 100M` | Rotate when the log reaches the specified size, when evaluated |
| `create` | Create a new log file after rotation |
| `copytruncate` | Copy the log and truncate the original file |

### Example configuration

```text
/var/log/myapp.log {
    daily
    rotate 7
    compress
    missingok
    notifempty
    create 0640 root adm
}
```

This configuration:
- Rotates the log daily.
- Keeps seven rotated files.
- Compresses old logs.
- Ignores a missing log file.
- Skips empty logs.
- Creates a new log file with the specified permissions and ownership.

### Test logrotate configuration

Debug mode:

```bash
sudo logrotate -d /etc/logrotate.conf
```

Force rotation:

```bash
sudo logrotate -f /etc/logrotate.conf
```

**Important:** Debug mode does not perform actual rotation. Force mode requests rotation immediately and should be used carefully, especially on production systems.

## 9. Linux System Monitoring

System monitoring means checking the health and performance of a Linux system.

DevOps engineers monitor:
- CPU usage.
- Memory usage.
- Disk usage.
- Running processes.
- Network activity.
- Application performance.

Monitoring helps identify performance problems before they cause major failures.

---

## 10. Monitoring CPU Usage

### 10.1 top

Displays running processes and system resource usage in real time.

```bash
top
```

Important information:
- CPU usage.
- Memory usage.
- Running processes.
- Process IDs.
- Load averages.

Useful keys inside top:

- `q` – Quit.
- `P` – Sort by CPU usage.
- `M` – Sort by memory usage.
- `k` – Send a signal to a process.

### 10.2 htop

An interactive process-monitoring tool with a more user-friendly interface.

```bash
htop
```

Installation examples:

Ubuntu/Debian:

```bash
sudo apt install htop
```

RHEL/Fedora systems:

```bash
sudo dnf install htop
```

The package manager and repository availability may vary by distribution.

### 10.3 uptime

Displays how long the system has been running and its load averages.

```bash
uptime
```

Example:

```text
10:30:00 up 5 days, 2:15, 2 users, load average: 0.50, 0.70, 0.60
```

Load averages represent the average system load over:

1. Last 1 minute.
2. Last 5 minutes.
3. Last 15 minutes.

**Important:** Load average is not the same as CPU percentage. Interpret it in relation to the number of CPU cores and the type of system workload.

## 11. Monitoring Memory Usage

### 11.1 free

Displays memory and swap usage.

```bash
free
```

Human-readable output:

```bash
free -h
```

Display memory information repeatedly:

```bash
free -h -s 2
```

This refreshes every two seconds.

Important fields:
- Total: Total available memory.
- Used: Memory currently used.
- Free: Completely unused memory.
- Available: Estimated memory available for new applications without swapping.

### 11.2 /proc/meminfo

Displays detailed memory information.

```bash
cat /proc/meminfo
```

Useful for investigating:
- Total memory.
- Available memory.
- Cached memory.
- Swap usage.

## 15. The /proc Filesystem

`/proc` is a virtual filesystem that exposes information about running processes and the Linux kernel.

It does not behave like an ordinary disk directory.

Examples:

```bash
cat /proc/cpuinfo
```

Displays CPU information.

```bash
cat /proc/meminfo
```

Displays memory information.

```bash
cat /proc/uptime
```

Displays system uptime information.

```bash
ls /proc
```

Displays available process and system information entries.

---

## 16. The /sys Filesystem

`/sys` is a virtual filesystem that exposes information about devices, drivers, and kernel subsystems.

Explore it using:

```bash
ls /sys
```

The `/sys` filesystem is commonly used to inspect hardware and kernel device information.

**Difference:**
- `/proc` mainly exposes process and kernel information.
- `/sys` mainly exposes device, driver, and kernel subsystem information.

## 17. Monitoring Tools Used in DevOps

Some commonly used monitoring tools include:

### 17.1 Prometheus

Prometheus is an open-source monitoring and alerting system.

It collects time-series metrics from configured targets and stores them for querying.

### 17.2 Grafana

Grafana is used to visualize metrics and create dashboards.

It can connect to data sources such as Prometheus.

Nagios is an infrastructure monitoring tool used to monitor hosts, services, and system availability.

- Elasticsearch.
- Logstash.

**Important distinction:**

## 18. Troubleshooting Using Logs and Monitoring

### Scenario 1: Application is not starting

Steps:

1. Check service status.

```bash
systemctl status nginx
```

2. Check service logs.

```bash
journalctl -u nginx -n 50
```

3. Check configuration.

```bash
sudo nginx -t
```

4. Investigate the error and fix the underlying problem.

### Scenario 2: Disk space is full

Check filesystem usage:

```bash
df -h
```

Find large directories:

```bash
sudo du -sh /var/log
```

Find large files:

```bash
sudo find /var/log -type f -size +100M
```

Inspect the files before removing or truncating anything.

### Scenario 3: High CPU usage

Check processes:

```bash
top
```

Find processes consuming CPU:

```bash
ps aux --sort=-%cpu | head
```

Investigate the process before terminating it.

### Scenario 4: High memory usage

Check memory:

```bash
free -h
```

Find memory-intensive processes:

```bash
ps aux --sort=-%mem | head
```

Investigate whether the application has a memory leak or excessive workload.

### Scenario 5: Application is not responding

Check the service:

```bash
systemctl status nginx
```

Check listening ports:

```bash
ss -tuln
```

Test the endpoint:

```bash
curl -I http://localhost
```

Check application logs:

```bash
journalctl -u nginx -f
```

### Scenario 6: SSH login failures

On Debian/Ubuntu:

```bash
sudo grep -i "failed" /var/log/auth.log
```

On many RHEL-based systems:

```bash
sudo grep -i "failed" /var/log/secure
```

Alternatively, inspect the system journal:

```bash
sudo journalctl -u ssh
```

The SSH service may be named `sshd` on some distributions:

```bash
sudo journalctl -u sshd
```

## 19. Sending Messages to the System Log

The `logger` command can send a message to the system logging facility.

Example:

```bash
logger "Testing Linux system logging"
```

Add a message with a tag:

```bash
logger -t devops-test "Application deployment started"
```

Search for the message in the journal:

```bash
journalctl -t devops-test
```

This is useful for testing logging configurations and scripts.

## 20. Best Practices for Logs and Monitoring

1. Monitor CPU, memory, disk, and network usage.
2. Check logs regularly.
3. Configure log rotation.
4. Monitor important services.
5. Investigate repeated errors.
6. Use dashboards for important metrics.
7. Configure alerts for critical problems.
8. Protect log files with suitable permissions.
9. Avoid storing passwords, tokens, and other secrets in logs.
10. Retain logs according to operational and security requirements.
11. Use centralized logging for systems spread across multiple servers.
12. Monitor disk space to prevent log files from filling the filesystem.

## 23. Linux Logs and Monitoring Interview Questions

### Q1. What are Linux logs?

Linux logs are records of system, application, and security events. They help administrators troubleshoot problems and monitor system activity.

### Q2. Where are Linux log files stored?

Most traditional Linux log files are stored inside `/var/log`.

### Q3. What is the purpose of the journalctl command?

`journalctl` is used to view and filter logs collected by systemd-journald.

### Q4. What is the difference between tail and tail -f?

`tail` displays the last lines of a file, whereas `tail -f` continuously displays new lines as they are added.

### Q5. What is log rotation?

Log rotation manages growing log files by rotating, compressing, and removing old log files according to configured policies.

### Q6. What is logrotate?

Logrotate is a Linux utility used to manage log rotation and prevent log files from consuming excessive disk space.

### Q7. What is the difference between /var/log and journalctl?

`/var/log` contains traditional log files, while `journalctl` is used to access logs stored in the systemd journal.

### Q8. How do you check CPU usage in Linux?

Use `top` or `htop` to monitor CPU usage and running processes.

### Q9. How do you check memory usage?

Use:

```bash
free -h
```

### Q10. How do you check disk usage?

Use:

```bash
df -h
```

### Q11. What is the difference between df and du?

`df` displays filesystem space usage, while `du` displays the space used by files and directories.

### Q12. What is dmesg?

`dmesg` displays messages from the Linux kernel ring buffer.

### Q13. What is the difference between logs and metrics?

Logs record individual events, while metrics represent numerical measurements collected over time.

### Q14. How do you monitor a service's logs?

Use:

```bash
journalctl -u service-name -f
```

### Q15. What would you do if a server's disk space became full?

I would first check filesystem usage with `df -h`, identify large directories using `du -sh`, locate large files, and inspect unnecessary files and old logs. I would then apply an appropriate cleanup or log rotation strategy without deleting important data.

### Q16. What would you do if CPU usage became very high?

I would use `top` or `ps aux --sort=-%cpu` to identify resource-intensive processes, investigate the cause, and take corrective action.

### Q17. What is Prometheus?

Prometheus is an open-source monitoring and alerting system used to collect and query time-series metrics.

### Q18. What is Grafana?

Grafana is a visualization platform used to create dashboards from monitoring data sources.

### Q19. What is the ELK Stack?

ELK stands for Elasticsearch, Logstash, and Kibana. It is commonly used for collecting, processing, searching, and visualizing logs.

### Q20. Why is monitoring important in DevOps?

Monitoring helps teams identify failures, detect performance issues, maintain service availability, and improve application reliability.
